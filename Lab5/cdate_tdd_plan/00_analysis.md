# Название этапа
Провести анализ задания и зафиксировать архитектуру CDate.

## Цель
После этапа есть полный список требований, формул и проектной структуры для TDD.

## Предусловие
Прочитать `task_date.md` полностью.

## Список задач
1. Выписать обязательные требования: все конструкторы, `GetDay/GetMonth/GetYear/GetWeekDay/IsValid`, все операторы из таблицы.
2. Выписать диапазон: только `01.01.1970 - 31.12.9999`.
3. Выписать правило: операции над invalid не меняют объект.
4. Выписать правило: выход за диапазон делает результат invalid.
5. Выписать ограничение: не использовать циклы для weekday и конвертаций туда-обратно.
6. Выписать допуск: цикл по месяцам внутри одного года допустим.
7. Выписать штрафы: коэффициент `0.6` за циклическое решение, `0.5` без автотестов.
8. Выбрать архитектуру `timestamp + valid` и обосновать:
   - упрощаются `+/-/++/--` (арифметика по одному числу);
   - упрощаются сравнения (сравнение timestamp);
   - меньше несогласованностей, чем при хранении `day/month/year`.
9. Описать валидность: `year in [1970,9999]`, `month in [1,12]`, `day in [1,daysInMonth(year,month)]`.
10. Описать формулы:
   - `isLeap = (y%4==0 && y%100!=0) || (y%400==0)`;
   - `leapsBefore(Y)=Y/4-Y/100+Y/400`;
   - `daysBeforeYear(y)=365*(y-1970)+(leapsBefore(y-1)-leapsBefore(1969))`;
   - `timestamp=daysBeforeYear(y)+daysBeforeMonth(y,m)+(day-1)`.
11. Описать `GetWeekDay` без циклов: `weekday=(4+timestamp)%7`, так как 01.01.1970 это Thursday (`4`).
12. Описать `timestamp -> (day,month,year)` без циклов по годам: формульный разбор григорианской даты (civil_from_days) и максимум цикл по месяцам.
13. Описать структуру проекта: `CDate.h/.cpp`, `DateUtils.h/.cpp`, `tests/CDateTests.cpp`, CMake-цель тестов.
14. Выбрать тестовый фреймворк (Catch2 или GoogleTest) и использовать один вариант на всех этапах.

## Тесты, которые нужно написать ДО реализации
1. `01.01.1970 <-> timestamp 0`.
2. `02.01.1970 <-> timestamp 1`.
3. Високосность: 2000=true, 1900=false, 2024=true, 2023=false.
4. Weekday: `01.01.1970=THURSDAY`, `04.01.1970=SUNDAY`.
5. Round-trip: `01.01.1970`, `29.02.2024`, `31.12.9999`.

## Критерий завершённости
Есть зафиксированный документ с требованиями, ограничениями, формулами, архитектурой и структурой проекта.

## Типичные ошибки
1. Неверно трактовать запрет на циклы и уйти в цикл по годам.
2. Забыть верхнюю границу 31.12.9999.
3. Смешать две стратегии invalid (флаг и исключения).
4. Ошибиться на `day-1` в формуле timestamp.
5. Не зафиксировать поведение invalid для всех операторов.
